## Compatibility and fail-closed rules

- Preserve the active `timeline.core` project/media DTOs and project persistence. The C++ schema-v1 codec is only for edit-core state, not a replacement application project file.
- No Kotlin edit calculation or divergent snap fallback is allowed. If the native library or JNI call is unavailable/rejected, timeline preview/commit/snap and clip/group lock actions fail closed. Track presentation/metadata controls remain Kotlin UI operations; group-lock state is represented by the native command/history protocol.
- C++ adapter conversion may translate persisted frame-count fields to Flicks at the JNI boundary. It must not invent media duration or coerce invalid edits into valid ones.
- Track rename/order/visibility/mute/solo/height and clip color/transform/adjustments remain application metadata/UI operations. They are not represented by the edit-core codec and still use Kotlin metadata snapshots.
- Group identity remains backward-compatible in `TimelineClip.metadata["linkedGroupId"]`; `TimelineClip.isGroupLocked` is a default-false serialized field so older project records retain their behavior. The adapter converts the persistent string ID to a collision-checked stable native ID, transmits the lock bit, and rejects a mismatched group ID on native result decode. Native `SetGroupLock` updates every member sharing a persistent ID (or one ungrouped clip), participates in native undo/redo, and allows unlocking protected content. Both canvases expose a long-press lock action and disable it when native is unavailable. No UI action currently creates/reassigns `linkedGroupId`, so the group action applies only to already-linked persisted clips; ungrouped clips get a clip-only lock. Payload, lock-target, and serialization compatibility tests are source-present but unrun; Android/JNI integration remains unverified.
- Build the Android target and run the guarded-source/Kotlin/UI tests before treating any source deprecation or JNI signature as verified.
